# ADR-0042. «Спросить советника»: живой голосовой помощник поверх данных MODUS FLOW

Дата: 2026-11-13 · Статус: принято в коде, голосовой провайдер **не подключён** (ветка `feat/kingdom-map`) · Запрос владельца от 13.11.2026: перенести подход IVAN CALL LIVE из Pavlodar Pulse в MODUS FLOW.

Номер 0042: номера 0030–0041 уже заняты в других ветках (`main`, `integration/living-knowledge`).

## Решение

Сотрудник нажимает «Спросить советника», говорит — и слышит короткий деловой ответ. Факты в ответе берутся только из MODUS FLOW: модель вызывает серверные инструменты, сервер исполняет их с правами этого сотрудника.

```
Браузер (WebRTC)                          Сервер MODUS FLOW                         OpenAI Realtime
  микрофон ── разрешён? ──► POST /voice/sessions ── лимиты ──► POST /realtime/client_secrets (основной ключ)
  SDP-предложение ────────► POST /voice/sessions/:id/sdp ────► POST /realtime/calls (краткоживущий секрет, один раз)
  ◄══════════════ голос и события: напрямую браузер ⇄ OpenAI (WebRTC) ══════════════►
  вызов функции из канала ─► POST /voice/sessions/:id/tools ── zod + RLS ── модули MODUS FLOW (только чтение)
  «Завершить» ────────────► DELETE /voice/sessions/:id ──────► POST /realtime/calls/:id/hangup
```

### Что взято из Pavlodar Pulse и что изменено
| IVAN CALL LIVE | MODUS FLOW |
| --- | --- |
| Серверный endpoint выдачи временного секрета | Тот же подход (`client_secrets`), но секрет **не уходит в браузер вообще**: сервер сам один раз передаёт с ним SDP. Страница сохраняет политику `connect-src 'self'`. |
| Режим симуляции с шаблонной «речью» без ключа | Убран. Без провайдера — «Голосовой AI не подключён» и текстовый режим. |
| `result = { success: true }` по умолчанию для инструмента | Убран. Неизвестный инструмент — ошибка `unsupported_tool` (400); модель слышит ошибку и обязана её назвать. |
| Инструменты исполнялись в браузере | Исполняются на сервере; браузер только пересылает имя и JSON-аргументы. |
| Устаревшие имена событий `response.audio_transcript.*` | Понимаются и они, и текущие `response.output_audio_transcript.*`, `output_audio_buffer.*`. |
| Телефония Twilio, звонки службам, городские инструменты | Не перенесены. |

Общий транспорт отделён от логики компании: `web/src/lib/realtimeTransport.ts` и `platform/modules/voice-realtime.ts` ничего не знают о MODUS FLOW; компания — в `platform/modules/voice.ts`, `voice-tools.ts`, `web/src/lib/voiceAdvisor.ts`, `web/src/components/VoiceAdvisor.tsx`.

### Инструменты (закрытый список, только чтение)
`get_my_summary`, `search_items`, `get_item`, `get_decision_history`, `search_meetings`, `get_council_open_items`, `get_council_brief`, `list_confirmed_impact`, `prepare_initiative_draft`, `prepare_council_question`.

- Человек берётся из токена, не из аргументов. Аргументы проверяет та же zod-схема, из которой сгенерировано описание для модели (`additionalProperties: false`: лишние поля — 422).
- Каждый инструмент вызывает существующие функции модулей (`searchItems`, `getIdea`, `listCouncil`, `getCouncil`, `listMeetings`/`getMeeting`, `listInbox`) в той же транзакции с RLS — советник не видит больше, чем сотрудник на экранах. Другая организация — 404, как везде.
- Ничто не пишет. «Черновик инициативы» и «вопрос для Совета» возвращаются как предложение `saved: false, requiresConfirmation: true`; сохранить черновик можно только кнопкой в панели (обычный `POST /lab/drafts`), внести вопрос в Совет — только самому на экране.
- «Подтверждённая польза» — только завершённая проверка эффекта с положительным итогом; одного статуса «внедрено» недостаточно.
- Тексты сотрудников в ответах инструментов помечены как данные, а не указания; длинные тексты обрезаются.

### Совет
У круглого стола — кнопка «Спросить советника о вопросе №…». Контекст проверяется правами сотрудника до платного вызова. Советник излагает суть, факты, доводы, варианты, риски, прошлые похожие случаи и черновик рекомендации; он не человек, не голосует, не руководитель и не принимает решений за Совет (это записано в инструкции и в ответе `get_council_brief`).

### Разговор ≠ запись совещания
Живой разговор не сохраняется на сервере: в журнале — только имя инструмента, число найденного и время, без слов сотрудника и без аргументов. История видна только в открытой панели. «Записать совещание» — отдельный экран с согласием каждого участника (ADR-0014, ADR-0015); в панели — только ссылка на него.

### Без подключения
`GET /voice/status` честно говорит, что подключено. Без голосового провайдера — «Голосовой AI не подключён» и текстовый режим: те же инструменты подбираются правилами по вопросу, ответ составляет существующая модель MODUS ADVISOR (ADR-0013, ADR-0028), ссылки — только на записи из найденных фактов. Без модели показываются найденные записи с пометкой «без пересказа ИИ».

### Включение (только по решению владельца)
| Переменная | Зачем |
| --- | --- |
| `MODUS_VOICE_PROVIDER=openai` | по умолчанию `none` |
| `OPENAI_API_KEY` (или `MODUS_VOICE_API_KEY`) | только на сервере; не в журнале, не в ответах, не в браузере |
| `MODUS_VOICE_ALLOW_REMOTE=true` | согласие: голос и факты уходят в OpenAI, это платно |
| `MODUS_VOICE_ALLOW_REAL_DATA=true` | второе согласие, обязательное вне демо-входа |
| `MODUS_VOICE_MODEL` / `MODUS_VOICE_VOICE` | `gpt-realtime` / `cedar` — стандартный синтетический мужской голос провайдера, не копия голоса человека |
| `MODUS_VOICE_MAX_SECONDS`, `MODUS_VOICE_SESSIONS_PER_HOUR`, `MODUS_VOICE_MAX_PER_USER`, `MODUS_VOICE_MAX_PER_ORG` | 600 с, 12 в час, 1 одновременно на человека, 5 на организацию; 60 вызовов инструментов на разговор |

Без явных переключателей сервер не стартует и объясняет, чего не хватает (как ADR-0028).

### Лимиты и отказоустойчивость
Лимиты проверяются до платного вызова (429 с понятной причиной). Серверная сессия создаётся только после того, как браузер получил микрофон. Секрет одноразовый (повторный SDP — 409), сессия чужого сотрудника или другой организации — 404, после срока — 404. По истечении срока сервер сам завершает звонок у провайдера. Ошибка подключения, обрыв связи, закрытие панели или страницы — все дорожки микрофона останавливаются, серверный слот освобождается. Ошибка провайдера показывается кодом, без текста провайдера.

## Проверки
- `test/platform/voice.test.ts` (PostgreSQL, 15 тестов): переключатели; закрытый список инструментов; «не подключён» без внешних вызовов; 401 и чужая организация; ключ и секрет не попадают в ответ; SDP проверяется до использования секрета, секрет одноразовый, завершение вызывает hangup; инструменты отвечают данными с правами сотрудника; «не найдено» без выдумок; чужие обращения недоступны ни поиском, ни по номеру, ни чужой сессией; изменение голосом невозможно, БД не меняется; лимиты; отказ провайдера; контекст Совета; текстовый режим; журнал без ключей и слов сотрудника; личный черновик не читается.
- `test/platform/voice-transport.test.ts` (без базы, в быстром шаге `verify.sh`, 9 тестов): микрофон запрещён/нет/небезопасный адрес; состояния и перебивание; `interrupt()`; ответы инструментов и ошибки без фиктивного успеха; mute; остановка освобождает все потоки; закрытие во время запроса микрофона; недоступный API; обрыв и переподключение; в клиенте нет симуляции, ключей и адреса провайдера.
- `web/e2e/voice-flow.mjs` (демо-сервер): панель, «не подключён», текстовый вопрос со ссылками, «не нашлось», круглый стол, телефон 375×812 без перекрытия панели разделов.
- `web/e2e/voice-media.mjs` (настоящий Chromium против тестового стенда `test/platform/support/voice-harness.ts`, где провайдер отказывает с 503): микрофон запрещён → сессия не создаётся; микрофон разрешён → сессия и SDP только через сервер → честная ошибка → все дорожки остановлены → переподключение без «уже идёт разговор».

## Ограничения (не скрываются)
- **С настоящим OpenAI Realtime не проверялось**: ключа нет, платный API без решения владельца не подключался. Форма запросов `client_secrets`/`calls`/`hangup` и разбор событий написаны по документации GA и проверены на подставных ответах. Голосового ответа в этой ветке никто не слышал.
- Критерий «нажал микрофон — услышал ответ по своим данным» будет выполнен только после включения переменных выше; до этого работает текстовый режим.
- Качество распознавания казахской речи и естественность голоса `cedar` на казахском не измерялись.
- Перебивание опирается на серверное определение речи провайдера (`interrupt_response`); эхо на телефонах без гарнитуры не измерялось.
- Сессии хранятся в памяти одного процесса: при нескольких экземплярах сервера лимиты считаются на экземпляр.
- Тексты обращений в результатах инструментов уходят в OpenAI на время разговора; поэтому реальные данные — только с отдельным `MODUS_VOICE_ALLOW_REAL_DATA=true`.
- Выбор инструментов в текстовом режиме — простые правила по словам вопроса; редкие формулировки могут не найти нужный инструмент (тогда работает поиск по словам).
- Проверено локально; GitHub CI не запускался.
