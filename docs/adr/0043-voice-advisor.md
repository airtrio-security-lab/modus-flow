# ADR-0043. «Спросить советника»: живой голосовой помощник поверх данных MODUS FLOW

Дата: 2026-11-13 · Статус: принято; проверено с настоящим OpenAI Realtime на демо-данных (без настоящего микрофона) (ветка `feat/kingdom-map`) · Запрос владельца от 13.11.2026: перенести подход IVAN CALL LIVE из Pavlodar Pulse в MODUS FLOW.

Номер 0043: номера до 0042 включительно заняты на `main` (ADR-0042 — «Ваш вклад признан»). В первом коммите ветки этот документ ошибочно назывался ADR-0042.

## Решение

Сотрудник нажимает «Спросить советника», говорит — и слышит короткий деловой ответ. Факты в ответе берутся только из MODUS FLOW: модель вызывает серверные инструменты, сервер исполняет их с правами этого сотрудника.

```
Браузер (WebRTC)                          Сервер MODUS FLOW                         OpenAI Realtime
  микрофон ── разрешён? ──► POST /voice/sessions ── лимиты ──► POST /realtime/client_secrets (основной ключ)
  SDP-предложение ────────► POST /voice/sessions/:id/sdp ────► POST /realtime/calls (краткоживущий секрет, один раз)
  ◄══════════════ голос и события: напрямую браузер ⇄ OpenAI (WebRTC) ══════════════►
  вызов функции из канала ─► POST /voice/sessions/:id/tools ── zod + RLS ── модули MODUS FLOW (только чтение)
  «Завершить» ────────────► DELETE /voice/sessions/:id ──────► POST /realtime/calls/:id/hangup
```

### Что взято из Pavlodar Pulse и что изменено
| IVAN CALL LIVE | MODUS FLOW |
| --- | --- |
| Серверный endpoint выдачи временного секрета | Тот же подход (`client_secrets`), но секрет **не уходит в браузер вообще**: сервер сам один раз передаёт с ним SDP. Страница сохраняет политику `connect-src 'self'`. |
| Режим симуляции с шаблонной «речью» без ключа | Убран. Без провайдера — «Голосовой AI не подключён» и текстовый режим. |
| `result = { success: true }` по умолчанию для инструмента | Убран. Неизвестный инструмент — ошибка `unsupported_tool` (400); модель слышит ошибку и обязана её назвать. |
| Инструменты исполнялись в браузере | Исполняются на сервере; браузер только пересылает имя и JSON-аргументы. |
| Устаревшие имена событий `response.audio_transcript.*` | Понимаются и они, и текущие `response.output_audio_transcript.*`, `output_audio_buffer.*`. |
| Телефония Twilio, звонки службам, городские инструменты | Не перенесены. |

Общий транспорт отделён от логики компании: `web/src/lib/realtimeTransport.ts` и `platform/modules/voice-realtime.ts` ничего не знают о MODUS FLOW; компания — в `platform/modules/voice.ts`, `voice-tools.ts`, `web/src/lib/voiceAdvisor.ts`, `web/src/components/VoiceAdvisor.tsx`.

### Инструменты (закрытый список, только чтение)
`get_my_summary`, `search_items`, `get_item`, `get_decision_history`, `search_meetings`, `get_council_open_items`, `get_council_brief`, `list_confirmed_impact`, `prepare_initiative_draft`, `prepare_council_question`.

- Человек берётся из токена, не из аргументов. Аргументы проверяет та же zod-схема, из которой сгенерировано описание для модели (`additionalProperties: false`: лишние поля — 422).
- Каждый инструмент вызывает существующие функции модулей (`searchItems`, `getIdea`, `listCouncil`, `getCouncil`, `listMeetings`/`getMeeting`, `listInbox`) в той же транзакции с RLS — советник не видит больше, чем сотрудник на экранах. Другая организация — 404, как везде.
- Ничто не пишет. «Черновик инициативы» и «вопрос для Совета» возвращаются как предложение `saved: false, requiresConfirmation: true`; сохранить черновик можно только кнопкой в панели (обычный `POST /lab/drafts`), внести вопрос в Совет — только самому на экране.
- «Подтверждённая польза» — только завершённая проверка эффекта с положительным итогом; одного статуса «внедрено» недостаточно.
- Тексты сотрудников в ответах инструментов помечены как данные, а не указания; длинные тексты обрезаются.

### Альфред
Советника зовут **Альфред** (решение владельца 13.11.2026): «Спросить Альфреда», «Альфред» в шапке телефона. Он представляется ИИ-помощником, не человеком.

### Два речевых провайдера
| | OpenAI Realtime | ElevenLabs Agents |
| --- | --- | --- |
| Включение | `MODUS_VOICE_PROVIDER=openai`, `OPENAI_API_KEY` | `MODUS_VOICE_PROVIDER=elevenlabs`, `ELEVENLABS_API_KEY`, `MODUS_VOICE_AGENT_ID=agent_7201m79ts6jvfnjrzdk07k4qsnb6` |
| Голос | стандартный синтетический `cedar` | **«Альфред Бетмен»** — клонированный голос из кабинета владельца в ElevenLabs |
| Что получает браузер | только id сессии; SDP идёт через сервер | подписанный URL одного разговора (краткоживущий секрет) и текст инструкций |
| Связь | WebRTC | WebSocket напрямую с `wss://api.elevenlabs.io` — политика страницы расширяется ровно этим адресом и только при этом провайдере |
| Модель | `gpt-realtime` | Claude Haiku 5.5 (настроена у агента) |
| Инструменты | описаны в сессии | 10 «клиентских» инструментов агента, созданы из тех же схем (`npm run voice:agent-tools`) |
| Исполнение инструментов | сервер MODUS FLOW, права сотрудника | то же самое |

**Права на голос.** «Альфред Бетмен» — клон голоса. Владелец подтвердил 13.11.2026, что права на этот клон у него есть; без этого подтверждения голос не подключался (запрет копировать голос реального человека без прав — из исходной задачи). Ответственность за права — на владельце.

**Агент ElevenLabs** «Альфред — советник MODUS FLOW» создан в рабочем пространстве владельца: приватный (вход только по подписанному URL), запись звука выключена, не больше 5 разговоров одновременно и 300 в день, разрешено переопределять только инструкции, первую реплику и язык. Инструкции для разговора (обращение, вступительный доклад) сервер MODUS FLOW отдаёт браузеру вместе с подписанным URL: инструкции — не граница безопасности, все факты по-прежнему идут через серверные инструменты.

**Запись о разговоре.** ElevenLabs сам ведёт запись о каждом разговоре (текст и краткий пересказ) — это проверено: после тестового разговора запись с пересказом осталась, несмотря на «хранение 0 дней». Режим нулевого хранения на тарифе владельца не включился (ошибка сервиса). Поэтому по окончании разговора сервер MODUS FLOW сам удаляет запись у провайдера (`DELETE /convai/conversations/:id`), проверив, что она принадлежит нашему агенту; до четырёх попыток в течение двух минут, итог — в журнале (`voice: provider_record`).

### Обращение и вступительный доклад
- Альфред обращается к сотруднику **только так, как тот сам выбрал** в «Как ко мне обращаться» (те же настройки, что у королевских посланий, ADR-0016): «мой милорд», «моя миледи», «мастер» или игровой титул; в деловом стиле — без игровых обращений. Пол по имени не угадывается. Титул меняет слова, не права.
- Разговор Альфред начинает сам, как дворецкий с утренним докладом: вызывает `get_my_summary` и говорит, например: «Мой милорд, у вас 12 открытых обращений, 2 просрочены. Я изучил их — вот итог: …». Числа — только из инструмента (`openItemsVisible`, `overdueItemsVisible` — то, что сотрудник видит по своим правам). За круглым столом вместо этого — суть вопроса и главные доводы.
- Вступление задаётся в инструкции сессии, а не в `response.create`: у OpenAI инструкции ответа заменяют инструкции сессии, и обращение потерялось бы.

### Чтобы было слышно, что связь работает
- Сразу после подключения Альфред начинает вступительный доклад: сотрудник сразу слышит, что звук идёт.
- Индикатор речи в режиме «Слушаю» показывает **настоящий уровень микрофона**; под ним — «Микрофон: слышу звук / тишина». Если за 9 секунд не было ни звука — подсказка проверить, какой микрофон выбран для сайта.
- «Слышу вас» — когда провайдер распознал начало речи; «Речь не распознана» — когда распознавание не удалось.
- В живом разговоре можно **написать вопрос** — он уходит в тот же разговор и получает голосовой ответ.

### Где вызывается
- Компьютер: плавающая кнопка «Спросить советника» справа внизу, панель — справа.
- Телефон: кнопка «Советник» в шапке справа, рядом с уведомлениями (на экранах уже 370 px — круглая кнопка с микрофоном и той же подписью для экранных читалок). Пока шапка видна, плавающей кнопки нет; когда шапка уехала при прокрутке, плавающая кнопка появляется над панелью разделов. Панель — нижний лист под панелью разделов, разделы остаются нажимаемыми.

### Совет
У круглого стола — кнопка «Спросить советника о вопросе №…». Контекст проверяется правами сотрудника до платного вызова. Советник излагает суть, факты, доводы, варианты, риски, прошлые похожие случаи и черновик рекомендации; он не человек, не голосует, не руководитель и не принимает решений за Совет (это записано в инструкции и в ответе `get_council_brief`).

### Разговор ≠ запись совещания
Живой разговор не сохраняется на сервере: в журнале — только имя инструмента, число найденного и время, без слов сотрудника и без аргументов. История видна только в открытой панели. «Записать совещание» — отдельный экран с согласием каждого участника (ADR-0014, ADR-0015); в панели — только ссылка на него.

### Без подключения
`GET /voice/status` честно говорит, что подключено. Без голосового провайдера — «Голосовой AI не подключён» и текстовый режим: те же инструменты подбираются правилами по вопросу, ответ составляет существующая модель MODUS ADVISOR (ADR-0013, ADR-0028), ссылки — только на записи из найденных фактов. Без модели показываются найденные записи с пометкой «без пересказа ИИ».

### Включение (только по решению владельца)
| Переменная | Зачем |
| --- | --- |
| `MODUS_VOICE_PROVIDER=openai` или `elevenlabs` | по умолчанию `none` |
| `OPENAI_API_KEY` / `ELEVENLABS_API_KEY` (или `MODUS_VOICE_API_KEY`) | только на сервере; не в журнале, не в ответах, не в браузере |
| `MODUS_VOICE_AGENT_ID` | только для ElevenLabs: id агента «Альфред» (не секрет) |
| `MODUS_VOICE_ALLOW_REMOTE=true` | согласие: голос и факты уходят провайдеру (и в языковую модель агента ElevenLabs), это платно |
| `MODUS_VOICE_ALLOW_REAL_DATA=true` | второе согласие, обязательное вне демо-входа |
| `MODUS_VOICE_MODEL` / `MODUS_VOICE_VOICE` | `gpt-realtime` / `cedar` — стандартный синтетический мужской голос провайдера, не копия голоса человека |
| `MODUS_VOICE_MAX_SECONDS`, `MODUS_VOICE_SESSIONS_PER_HOUR`, `MODUS_VOICE_MAX_PER_USER`, `MODUS_VOICE_MAX_PER_ORG` | 600 с, 12 в час, 1 одновременно на человека, 5 на организацию; 60 вызовов инструментов на разговор |

Без явных переключателей сервер не стартует и объясняет, чего не хватает (как ADR-0028).

### Лимиты и отказоустойчивость
Лимиты проверяются до платного вызова (429 с понятной причиной). Серверная сессия создаётся только после того, как браузер получил микрофон. Секрет одноразовый (повторный SDP — 409), сессия чужого сотрудника или другой организации — 404, после срока — 404. По истечении срока сервер сам завершает звонок у провайдера. Ошибка подключения, обрыв связи, закрытие панели или страницы — все дорожки микрофона останавливаются, серверный слот освобождается. Ошибка провайдера показывается кодом, без текста провайдера.

## Проверки
- `test/platform/voice.test.ts` (PostgreSQL, 15 тестов): переключатели; закрытый список инструментов; «не подключён» без внешних вызовов; 401 и чужая организация; ключ и секрет не попадают в ответ; SDP проверяется до использования секрета, секрет одноразовый, завершение вызывает hangup; инструменты отвечают данными с правами сотрудника; «не найдено» без выдумок; чужие обращения недоступны ни поиском, ни по номеру, ни чужой сессией; изменение голосом невозможно, БД не меняется; лимиты; отказ провайдера; контекст Совета; текстовый режим; журнал без ключей и слов сотрудника; личный черновик не читается.
- `test/platform/voice-transport.test.ts` (без базы, в быстром шаге `verify.sh`, 9 тестов): микрофон запрещён/нет/небезопасный адрес; состояния и перебивание; `interrupt()`; ответы инструментов и ошибки без фиктивного успеха; mute; остановка освобождает все потоки; закрытие во время запроса микрофона; недоступный API; обрыв и переподключение; в клиенте нет симуляции, ключей и адреса провайдера.
- `web/e2e/voice-flow.mjs` (демо-сервер): панель, «не подключён», текстовый вопрос со ссылками, «не нашлось», круглый стол, телефон 375×812 без перекрытия панели разделов.
- `web/e2e/voice-media.mjs` (настоящий Chromium против тестового стенда `test/platform/support/voice-harness.ts`, где провайдер отказывает с 503): микрофон запрещён → сессия не создаётся; микрофон разрешён → сессия и SDP только через сервер → честная ошибка → все дорожки остановлены → переподключение без «уже идёт разговор».

## Проверка с настоящим OpenAI Realtime (13.11.2026, демо-данные, ключ владельца)
Владелец включил голос (`MODUS_VOICE_PROVIDER=openai`, `MODUS_VOICE_ALLOW_REMOTE=true`, демо-вход). Проверено во встроенном браузере Claude (Chromium) с **беззвучным подставным микрофоном** — настоящий микрофон там недоступен:
- `client_secrets` → 201, SDP через сервер → 201, ICE и DTLS подключены, канал данных открыт, `session.created`, удалённая аудиодорожка пришла;
- приветствие Альфреда пришло голосом и текстом;
- вопрос «Что сегодня требует моего внимания?» → модель сама вызвала `get_my_summary` → ответ по данным демо (7 непрочитанных уведомлений, свежие предложения) и 4 ссылки;
- вопрос текстом в живом разговоре «Какие обращения склада просрочены?» → `search_items` → «одно просроченное обращение на складе: „На второй смене не хватает сканеров“… решение ждут от Айгерим Нурлановой», ссылка №16.

Первые два разговора владельца с настоящим микрофоном завершились без единого вызова инструмента: провайдер не получил вопроса голосом. Причина в браузере владельца не установлена (вероятнее всего — выбран не тот микрофон); после этого добавлены индикатор уровня микрофона, подсказка и приветствие.

## Проверка с настоящим ElevenLabs (13.11.2026, демо-данные)
Во встроенном браузере Claude, с беззвучным подставным микрофоном, через тестовый стенд с подписанным URL одного разговора (ключа ElevenLabs у сервера ещё не было):
- подключение по WebSocket, инструкции приняты, политика страницы пропустила ровно `wss://api.elevenlabs.io`;
- вступительный доклад голосом «Альфред Бетмен» (41 аудиофрагмент): «Мой милорд, у вас тринадцать открытых обращений, из них четыре просрочены. Я изучил их, вот итог: …» — после вызова `get_my_summary`, 4 ссылки в панели;
- вопрос текстом в том же разговоре → `search_items` → «в доступных вам данных MODUS FLOW отклонённого предложения по логистике не нашлось»;
- «Завершить» закрывает соединение.

Не проверено с настоящим ElevenLabs: получение подписанного URL ключом сервера и удаление записи разговора (оба запроса проверены только на подставных ответах); распознавание речи с настоящего микрофона; перебивание голосом; казахский язык (распознавание у агента настроено на русский).
В кабинете ElevenLabs осталась запись тестового разговора `conv_3501m79v3sreffvb6ezcp49st8r1` (демо-данные).

## Ограничения (не скрываются)
- **Распознавание речи с настоящего микрофона и перебивание голосом не проверены** — ни в одной автоматической проверке нет настоящего микрофона; это проверяет человек.
- Завершение звонка у провайдера (`hangup`) отвечало 5–6 секунд; на работу панели не влияет (запрос не ждётся), причина не исследована.
- Качество распознавания казахской речи и естественность голоса `cedar` на казахском не измерялись.
- Перебивание опирается на серверное определение речи провайдера (`interrupt_response`); эхо на телефонах без гарнитуры не измерялось.
- Сессии хранятся в памяти одного процесса: при нескольких экземплярах сервера лимиты считаются на экземпляр.
- Тексты обращений в результатах инструментов уходят в OpenAI на время разговора; поэтому реальные данные — только с отдельным `MODUS_VOICE_ALLOW_REAL_DATA=true`.
- Выбор инструментов в текстовом режиме — простые правила по словам вопроса; редкие формулировки могут не найти нужный инструмент (тогда работает поиск по словам).
- Проверено локально; GitHub CI не запускался.
