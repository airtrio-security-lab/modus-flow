# ADR-0026. «3D-город»: реальная трёхмерная сцена Содружества и импорт официального набора

Дата: 2026-11-12 · Статус: принято (ветка `feat/kingdom-map`, в `main` не влито) · ТЗ владельца: «MODUS FLOW — MASTER BUILD BRIEF / 3D LIVING COMMONWEALTH»

## Контекст

До этого город был SVG-схемой (ADR-0019…0021). ТЗ требует настоящий интерактивный 3D-мир на десктопе и телефоне: реальные объекты, материалы, камера, клики по зданиям — без растровой картинки с невидимыми зонами. При этом движок не имеет права назначать людей, менять статусы, начислять XP и обходить права.

## Решение

### Стек
- **Three.js 0.169 напрямую, без React Three Fiber и Drei.** Сцена строится императивно (процедурные «строители» зданий, слияние геометрии по материалам, ручное управление шейдерами теней и освобождением ресурсов). R3F добавил бы слой согласования React и ~150 КБ ради декларативности, которая здесь не нужна: React отвечает только за HUD и панели. Three.js подгружается лениво, только при открытии 3D (чанк ~600 КБ, ~160 КБ gzip).
- **Собственный процедурный пайплайн вместо Blender/GLB.** Вся геометрия и все PBR-текстуры (цвет + карта нормалей) создаются кодом в браузере. В репозитории нет ни одного стороннего 3D-ассета и ни одной чужой текстуры — вопросов лицензий нет. Цена решения записана в «Ограничениях».
- Бэкенд и PostgreSQL не менялись ради графики: сцена читает тот же `GET /kingdom`, что схема и таблица.

### Слои
`доменные события → read-модель /kingdom → World.setData / setEnvoys → сцена → HUD (React) → существующие экраны и API`.
`web/src/world3d/`: `tex.ts` (материалы), `geo.ts` (геометрия, `Builder`), `kits.ts` (4 цивилизации × 5 уровней, центр), `terrain.ts` (рельеф, река, дороги, мосты, лес, небо), `world.ts` (сцена, камера, выбор объектов, гонцы), `kitview.ts` (один замок для «Цитадели»). Движок ничего не знает о правах и не вызывает API.

### Что откуда берётся
| На экране | Источник |
| --- | --- |
| Район, его цивилизация | `castles[].civilization` (выбор отдела, 0014/0015) |
| Архитектурная стадия 1…5 | `castles[].level` — считает сервер по порогам из настроек организации |
| Гонец и его место на дороге | открытое обращение и его реальный статус (`envoyState`) |
| Красный вымпел | просрочен первый ответ или решение |
| Пьедесталы на площади | число выданных достижений |
| Счётчики HUD | те же обращения и XP; «уровня Содружества» в системе нет — он не показан |

### Режимы и запасной путь
Страница «Город» имеет три вида: **3D-город**, **Схема** (прежняя SVG-карта), **Рабочее пространство** (таблица). 3D открывается по умолчанию там, где есть WebGL; при `prefers-reduced-motion`, включённой «облегчённой графике» — схема; без WebGL или при потере графического контекста — схема с объяснением. Выбор человека хранится на устройстве (`modus.kingdom.view`; прежний ключ `modus.kingdom.mode` со значением «карта» не мешает открыть 3D, значение «таблица» переносится), уровень качества можно закрепить (`modus.w3d.quality`: low/medium/high).

### Производительность
Геометрия района сливается в один меш на материал; лес — три `InstancedMesh`; карта теней статична (перерисовывается только при перестройке); DPR ограничен (2 / 1.5 / 1) и автоматически снижается при длинных кадрах; в фоновой вкладке цикл остановлен; при «уменьшить движение» кадр рисуется только по изменению; при уходе со страницы освобождаются геометрия, материалы, текстуры и контекст.

### Импорт официального набора (миграция 0017)
`dataset_items` — отдельное пространство имён: (организация, набор, внешний ID) → обращение, плюс исходные тип, категория, приоритет, условный статус, автор и ответственный по набору. Строки проходят через обычные сервисы (подача, маршрутизация по категории, отзывы, решения). Повторный импорт ничего не дублирует. XP из набора не начисляется; «Реализовано» доводится только до «в работе». Демо-подтверждение — отдельный запрошенный шаг `--demo-confirm`, выполняет настоящий шаг «внедрение завершено» и помечается в данных и на экране.

## Ограничения (не скрываются)
1. **Визуальный уровень.** Это процедурная графика реального времени в стиле сдержанной исторической стратегии. Она не достигает живописной детализации референса `02_desktop_cinematic_reference.png`: нет скульптурных моделей, фотограмметричных текстур, объёмного тумана, водопадов, анимированных жителей и флагов. Чтобы дойти до уровня референса, нужны авторские модели (Blender → glTF) — это отдельная художественная работа.
2. **Производительность не измерена на видеокарте и телефоне.** В среде разработки доступен только программный WebGL (SwiftShader, 2 ядра): 0.2–10 кадров/с в зависимости от уровня качества. Эти числа не относятся к реальным устройствам; целевые 60/30 кадров/с не подтверждены и не опровергнуты.
   Дополнение 2026-11-12: На видеокарте сцена измерена один раз, 2026-11-12: Chrome на Apple M5 (Metal), холст 2559×1439, высокое качество — около 600 тыс. треугольников и 154 вызова отрисовки; за 12 секунд перелётов камеры интервал между кадрами: медиана 5 мс, p90 10 мс, p99 15 мс, один кадр дольше 33 мс. Замер сделан на сборке до Русского царства и города района; слабые видеокарты и реальные телефоны не измерялись.
3. Телефон проверен только в эмуляции Chromium (390×844, касания), не на устройстве.
4. Кинематографический вход в Совет из района (`?enter=`) пока идёт в режиме схемы.
5. Гонцы стоят на этапе маршрута, а не идут: движение вдоль дороги не анимировано.
6. В портретной ориентации обзор показывает центр и ближние районы; остальные — жестом или списком.
