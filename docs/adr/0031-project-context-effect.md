# ADR-0031 · От инициативы к измеримому результату: контекст проекта, затронутые подразделения, измеренный эффект

Status: accepted for a Draft PR (owner brief «PRODUCT REFINEMENT», 2026-11-12). Не влито в `main`.

## Контекст

Заказчик хакатона — проектная компания: проектирование, поставка, пусконаладка, сопровождение. Это публичные
сведения о бизнесе, а не подтверждённые внутренние требования. Задача — показать, что MODUS FLOW доводит идею
сотрудника до проверяемого результата. Это не новый продукт, не ERP и не реестр проектов.

## Аудит: что уже было

| Требование | Что уже есть | Что добавлено |
| --- | --- | --- |
| Контекст проекта при подаче | Тема и подразделение для маршрутизации (`ideas.category_id`, `department_id`) | Необязательные «проект или объект» и «этап работы» — `idea_contexts`; блок «Связать с проектом» в форме, в Зале воинов и на карточке |
| Затронутые подразделения | Нет; подразделение у обращения одно — ответственное | `idea_affected_departments`, отдельно от ответственного; прав не дают |
| Измерение эффекта | `verifications` + `verification_evidence` (исходное/результат, показатель, значение, единица), только до решения; `effect_approvals` — бонус от ответственного за решение | Период, источник, направление улучшения, отметка сопоставимости в тех же доказательствах; сводка «до/после»; измерение после решения — существующая проверка `impact` |
| Межотдельское обсуждение | Совет, малые советы и Большой стол, заседания с правами приглашения, анкеты навыков | Подсказка «кого можно пригласить» по правилам; та же панель в Совете |
| Связь с Библиотекой | Черновик записи из обращения (`knowledge-draft`), права Архивариуса | Предложение после подтверждённого внедрения; сопоставимые измерения в черновике |

## Решение

1. **Контекст — заметка, а не сущность проекта.** Две необязательные строки, записываются один раз (автором
   обращения, тем, от чьего имени оно подано, ведущим или ответственным за решение) и не редактируются: видно,
   кто и когда их назвал. Бюджетов, договоров и графиков нет. В журнал аудита попадает факт, а не название
   проекта.
2. **Ответственное подразделение и затронутые хранятся раздельно.** `ideas.department_id` по-прежнему
   выбирают правила маршрутизации. Затронутые — отдельная таблица только для добавления; ответственное
   подразделение в неё добавить нельзя (проверка в сервисе и триггер). Никаких прав, уведомлений и
   назначений из этой отметки не следует.
3. **Одна система доказательств.** В `verification_evidence` добавлены четыре необязательных столбца:
   `period`, `source`, `goal` (у исходного измерения: значение должно снизиться или вырасти), `comparable`
   (у результата: измеривший подтверждает, что период и условия сопоставимы). Записи остаются только для
   добавления.
4. **Сводка эффекта считается строго** (`platform/domain/effect.ts`):
   - нет «до» или «после» — «Эффект пока не измерен», не ноль;
   - разные единицы или нет отметки сопоставимости — разница и процент не считаются;
   - каждая метрика — отдельная строка, ничего не складывается: снижение затрат не смешивается с ростом
     выручки;
   - «улучшение» пишется только когда у исходного измерения названо направление; при нулевом «до» процента
     нет.
5. **Измерение после решения — существующая проверка `impact`.** Её запускает ведущий обращения (то же право,
   что у пилота), пока идёт внедрение или после его подтверждения; измеряет не автор и не ответственный за
   решение. Завершение измерения не меняет стадию и ничего не решает. Бонус за эффект по-прежнему подтверждает
   только ответственный за решение (`effect_approvals`), один раз. Для этого ослаблено одно условие в
   `verifications_guard_insert`: `impact` разрешён и на стадии `impact_verification`.
6. **Подсказка — не назначение.** `GET /ideas/:n/specialists`: руководители затронутых подразделений — всем,
   кто видит обращение; коллеги с подходящим навыком из собственной анкеты — только ведущему и ответственному
   за решение (как подбор исполнителей). Метод подписан «по правилам, без ИИ». Заседание созывает человек с
   таким правом, существующим маршрутом.
7. **Библиотека.** После подтверждённого внедрения карточка предлагает «Сохранить полученный опыт в Библиотеку
   знаний». Кнопку видят те, кто и раньше мог вносить записи; остальные — пояснение. Черновик собирается
   существующим маршрутом, в него добавляются только сопоставимые измерения одной фразой. Личные заметки,
   вложения и несопоставимые числа не переносятся; запись не создаётся и не принимается автоматически.

## Что намеренно не сделано (вопросы владельцу)

- **Подтверждение эффекта без измерений остаётся возможным.** Это действующее бизнес-правило (ADR-0012).
  Карточка честно показывает «Эффект пока не измерен» рядом с подтверждённым бонусом. Запрещать подтверждение
  без измерений — изменение правила, нужно решение владельца.
- **Контекст нельзя исправить.** Он записывается один раз. Если нужна правка с историей — отдельное решение.
- **Затронутые подразделения не уведомляются.** Иначе отметка стала бы способом рассылки. Приглашение — через
  заседание.
- **ИИ не предлагает метод оценки.** Подключённая модель («Оценка ИИ», ADR-0027) по-прежнему оценивает решение
  целиком; отдельной подсказки «как измерить» нет. Чисел модель не создаёт нигде.
- **Этап работы — фиксированный список** из брифа; справочника этапов в настройках нет.
- **Демо-кейс не входит в сид.** Он проигрывается сценарием `npm run demo:refinement` на свежих демо-данных и
  помечен как учебный в каждом тексте.

## Проверки

`test/platform/effect.test.ts` (5, без базы), `test/platform/refinement.test.ts` (8, PostgreSQL),
`web/e2e/refinement-flow.mjs` (8 шагов, десктоп и телефон). Соответствие пунктам брифа:
обычное обращение без контекста; сохранение и показ контекста; изоляция организаций; приватность заметок Зала
воинов; эффект без измерений не «измерен»; несопоставимые числа без процента; решение и подтверждение только с
полномочиями; повторный запрос без дубликатов; Совет, Библиотека и Зал воинов — их прежние тесты и сценарии;
телефон 390×844 без горизонтальной прокрутки. Проверки локальные: GitHub CI не запускается.
