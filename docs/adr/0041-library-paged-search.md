# ADR-0041 · Каталог Библиотеки: серверные страницы и точные числа

Status: accepted (задание владельца, 2026-11-13).

## Было

`GET /knowledge` отдавал до 200 записей одним ответом; зал выбирался в браузере, счётчики залов и «найдено»
считались по загруженной части. При тысячах записей числа были бы неверны.

## Решение

- `limit` (1–60, по умолчанию 24) и `offset`; порядок полный и устойчивый: оценка совпадения, дата изменения,
  затем `id` — строка не повторяется и не пропадает между страницами. В интерфейсе — «Показать ещё».
- Ответ несёт точные числа из базы: `total` для текущих фильтров и счётчики трёх залов. Счётчики залов намеренно
  не зависят от выбранного зала: «во всех залах» и один зал согласованы. Все числа считаются под RLS — это число
  доступных читателю записей, не размер библиотеки.
- Зал — такой же серверный фильтр, как тип и состояние. Зал, запрос, тип и состояние хранятся в адресе.
- Поиск по номеру обращения-источника («№126»): только через `idea_overview`, то есть среди обращений, которые
  читатель может открыть; поиск не подтверждает существование закрытого источника.
- Поиск остаётся поиском по словам (русская морфология PostgreSQL и близость написания). Семантическим он не
  называется; векторная база не вводилась — необходимость не подтверждена.

## Ограничения

`OFFSET` линейно дорожает на очень глубоких страницах; при каталоге в десятки тысяч записей потребуется
постраничный ключ. Поиск по тексту источников (заседаний, обсуждений) не делается: их содержание закрыто
правилами доступа самих источников.
