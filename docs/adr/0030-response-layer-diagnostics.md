# ADR-0030. Отклик 3D-города, память прошлого визита, диагностика на устройстве, правила по путям

Дата: 2026-11-12 · Статус: принято · Запрос владельца от 12.11.2026: посмотреть три открытых набора навыков для игровой разработки и применить лучшее

## Контекст

Просмотрены три репозитория:

- `majidmanzarpour/threejs-game-skills` — девять навыков для браузерных игр на Three.js (режиссёр, геймплей и «ощущение игры», графика, интерфейс, отладка и профилирование, проверка и выпуск, три генератора ассетов);
- `gamedev-skills/awesome-gamedev-agent-skills` — 77 навыков по движкам, дисциплинам и жанрам;
- `Donchitos/Claude-Code-Game-Studios` — шаблон «студии» для Claude Code: 49 агентов, 74 команды, хуки, правила по путям, шаблоны документов.

MODUS FLOW — не игра, а рабочая система с игровым экраном над теми же данными (ADR-0011, 0026). Поэтому из игровых практик берётся только то, что помогает читать состояние и доказывать качество, и не берётся ничего, что принимает решения или шумит.

ADR-0026 честно называл три слабых места 3D-города: гонцы «стоят, а не идут» (ограничение 5), производительность на настоящей видеокарте и телефоне не измерена (ограничение 2), в сцене нет движения. Все три закрываются практиками из этих наборов.

## Решение

### 1. Слой отклика (`web/src/world3d/feel.ts`)
Источник: `threejs-gameplay-systems/references/game-feel.md` и `disciplines/game-feel`.

Отклик — короткое сглаженное движение в ответ на **реальное событие данных**. Событие определяется сравнением двух ответов сервера, а не таймером и не случайностью:

| Событие (что сказал сервер) | Отклик в сцене | Ступень |
| --- | --- | --- |
| У обращения изменился этап | гонец идёт по своей дороге от прежнего места к новому, карточка над головой идёт с ним | средняя |
| Появилось новое открытое обращение | гонец появляется на месте | малая |
| Обращение закрыто | гонец уходит | малая |
| Уровень отдела стал **выше** | новая постройка «встаёт» с небольшой пружиной, по плато расходится кольцо | большая |
| Человек выбрал район | кольцо выбора «садится» на место | малая |
| Изменилось число в нижней панели | цифра коротко пульсирует | малая |

Правила слоя (проверяются тестами):
- отклик никогда не блокирует ввод: камера и клики работают во время движения;
- каждое движение кончается ровно в состоянии покоя — там же, где объект стоял бы без анимации;
- два движения одного объекта не спорят: новое сначала доводит старое до конца;
- время — настоящая дельта кадра; `Math.random` в слое запрещён;
- при «уменьшить движение» и «облегчённой графике» слой не запускается; если движение выключили на ходу, всё сразу приходит в покой;
- ступени пропорциональны: обычные действия тихие, заметен только рост замка. Понижение уровня и перестройка без роста отклика не дают.

Движок по-прежнему ничего не решает: `World` получает районы, уровни и места гонцов и только сравнивает их с предыдущими.

### 2. Память прошлого визита (`web/src/lib/citySeen.ts`)
Раньше рост замка показывался, только если человек смотрел на город в момент изменения. В демо так не бывает: решение принимают на странице обращения, а в город возвращаются потом — и город открывался неподвижным.

Теперь экран помнит **на этом устройстве**, что человек видел в прошлый раз: уровни отделов и место каждого гонца (ключ `modus.city.seen.<организация>.<участник>`). При следующем входе первый ответ сервера сравнивается с этой памятью, и после паузы в 1,1 с показывается ровно то, что изменилось: выросший замок встаёт, гонец идёт от места, где его видели, новый появляется. Сообщение «Улучшение замка» (уже существовавшее) теперь тоже срабатывает после возвращения — в 3D и в схеме.

Память — не источник истины. Без неё, в чужом браузере или после очистки данных город просто открывается неподвижным. Гонец узнаётся по номеру и времени публикации обращения: после пересоздания демо-базы тот же номер не считается «тем же гонцом, который перешёл».

### 3. Диагностика на устройстве (`web/src/components/W3dDiag.tsx`, `web/src/world3d/budget.ts`)
Источник: `threejs-debug-profiler` (порядок профилирования, объект диагностики) и `threejs-qa-release` (бюджеты, замер на сборке, служебный интерфейс скрыт от пользователя).

Служебная панель открывается только по адресу `#/kingdom?diag=1` (или `modus.w3d.diag = 1` на устройстве) и в показ не входит. Показывает медиану и 90-й процентиль времени кадра, вызовы отрисовки и треугольники относительно бюджета уровня, разрешение и плотность пикселей, графический адаптер; умеет закрепить уровень качества, сделать замер одной и той же сцены (весь город, 8 с) и скопировать отчёт. Программную отрисовку называет прямо: её время кадра не показатель.

Бюджет демо-города (8 районов, около 30 гонцов), замер 12.11.2026 в стенде наборов (8 районов, 21 гонец):

| Уровень | Вызовы: замер / бюджет | Треугольники: замер / бюджет |
| --- | --- | --- |
| low | 147 / 220 | 295 тыс. / 450 тыс. |
| medium | 147 / 220 | 440 тыс. / 650 тыс. |
| high | 147 / 220 | 649 тыс. / 950 тыс. |

Время кадра: до 20 мс — «плавно» (60 к/с), до 36 мс — «приемлемо для телефона» (30 к/с), дольше — совет закрепить уровень ниже, а на низком уровне — показывать «Схему».

### 4. Правила для Claude по путям и чек-лист показа (`docs/claude/` → `.claude/`)
Источник: `Claude-Code-Game-Studios` (правила с областью действия по путям, проверка «ворот» перед этапом, правило «видимое изменение закрыто только после запуска и сохранённого снимка»).

Заготовки лежат в `docs/claude/`; чтобы Claude Code их подхватывал, владелец копирует их в `.claude/` одной командой (см. `docs/claude/README.md`) — удалённый сеанс Claude в `.claude/` писать не может. Четыре коротких файла правил подгружаются только при работе с соответствующими путями: 3D-движок, веб-интерфейс, платформа, решения и документы. Они не вводят новых решений — собирают в одном месте уже принятые (ADR-0002, 0005, 0010, 0011, 0026 и это). Навык `demo-gate` — порядок проверки перед показом с честным вердиктом «готово / есть замечания / не готово».

## Что не взято и почему

| Практика | Почему нет |
| --- | --- |
| Тряска камеры, «заморозка удара», рывок угла обзора, вспышки на весь экран | В рабочем инструменте это шум и риск укачивания; арт-дирекция (`docs/3d/art-direction.md`) требует сдержанности; вспышки упираются в WCAG 2.3.1 |
| Генераторы 3D-моделей, изображений и звука через платные API (Tripo, Gemini, ElevenLabs) | ADR-0026: в репозитории нет сторонних ассетов и вопросов лицензий; ключи и платные вызовы за четыре дня до показа — лишний риск |
| Иерархия из 49 агентов, 74 команд и 15 хуков | Объём процесса больше самой задачи; у проекта уже есть `scripts/verify.sh`, git-хуки и сквозные сценарии. Сам автор шаблона по умолчанию ставит режим `minimal` |
| Навыки по Godot, Unity, Unreal, Roblox и жанровые шаблоны | Не наш стек |
| Бот-прохождение игры, скриншотные эталоны с попиксельным сравнением | Игрового цикла нет; сцена процедурная и на программной отрисовке даёт шум — проверяются состояния и числа, а не пиксели |
| Звук отклика | Требует ассетов, согласия на автозвук и настройки громкости; не до показа |

## Ограничения (не скрываются)
1. Отклик проверен только на программной отрисовке (SwiftShader). На настоящей видеокарте и телефоне не запускался; для этого и сделана панель диагностики. **Замер на ноутбуке показа и на телефоне ещё не выполнен.**
2. Гонец «идёт» скольжением с покачиванием: ног и анимации шага нет (модель — процедурная фигурка, ADR-0026).
3. Память прошлого визита живёт на устройстве. На другом устройстве изменения не будут показаны как «новые».
4. Если человек смотрит на город, изменения приходят с опросом раз в 15 секунд (как и раньше); отклик начинается в этот момент.
5. Кольцо роста видно в пределах плато района; при дальнем обзоре оно тонкое.
6. Бюджеты заданы для демо-города. Для организации с другим числом отделов их надо измерить заново.
7. Правила начинают действовать только после копирования из `docs/claude/` в `.claude/` и только на работу Claude Code в этом репозитории; люди их не обязаны читать, а CI их не проверяет.

## Проверки
- `test/platform/world3d.test.ts` (9, без базы и браузера): движение кончается ровно в покое; один ключ — одно движение; задержка и удержание начальной позы; `settle` и `drop`; длинный кадр; ступени пропорциональны; чтение замера по бюджету. Входит в быструю проверку (`scripts/verify.sh --quick`) и в `npm run test:platform`.
- `web/e2e/feel-flow.mjs` (`npm run demo:feel`, без базы): настоящий движок в стенде `web/dev/world.html` — сцена в бюджете; гонец идёт от прежнего места и встаёт туда же, куда встал бы без анимации; камера при этом слушается; новый гонец появляется, закрытый уходит; замок растёт только при повышении уровня; кольцо выбора; «уменьшить движение»; память прошлого визита показывает ровно изменившееся. Снимки: `docs/demo/feel/` (низкий уровень качества, 420×280 — это доказательство состояния, а не витрина).
- `web/e2e/world3d-flow.mjs` (`npm run demo:world3d`, свежая демо-база с набором): все прежние шаги пройдены на изменённой сборке; добавлен шаг 9 через настоящий экран — первый визит неподвижен; «в прошлый раз» замок был ниже, гонец стоял на другом этапе, а одного ещё не было → сообщение «Улучшение замка», движок получает память, всё кончается там, где говорит сервер; память у каждого своя; панель диагностики есть только по `?diag=1`, читает бюджет, называет программную отрисовку, убирается.
- Где запускалось: Linux, Node 22.23, PostgreSQL 16, Chromium с программным WebGL (SwiftShader), 12.11.2026. На macOS владельца и в GitHub CI эти изменения не запускались.
