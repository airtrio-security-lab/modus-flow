# ADR-0033 · Демо по ссылке: Vercel + Neon

Status: accepted (решение владельца, 2026-11-13): «задеплоим в Vercel вместо opora»; способ — Vercel + Neon;
доступ — открыто всем; проект opora поставлен на паузу.

## Контекст

До сих пор демо запускалось только локально (`scripts/demo-local.sh`, docker compose). Владелец решил показать
его по ссылке. Платформа — один долгоживущий Node-процесс (API + `web/dist`, ADR-0005) и PostgreSQL с RLS.

## Решение

- **Интерфейс** — статикой на CDN Vercel (`web/dist`), с теми же заголовками, что даёт `platform/http/static.ts`
  (CSP берётся из него же: `PAGE_CSP` экспортирован).
- **API** — одна Vercel Function `api/index.mjs` из `deploy/vercel/entry.ts`: тот же `createApp`, что в
  `platform/main.ts`, без копий логики. Регион `fra1`, рядом с базой.
- **Сборка** — только упаковка: `deploy/vercel/build.mjs` собирает функцию esbuild'ом (из инструментов vite,
  новой зависимости нет) в каталог **вне** репозитория. Сама платформа по-прежнему TypeScript без сборки.
- **База** — Neon (`aws-eu-central-1`, PostgreSQL 16), отдельный проект `modus-flow-demo`. API ходит под
  непривилегированной ролью `modus_api` (член `modus_app`) через пулер Neon; `assertUnprivilegedConnection`
  проверяет это при старте, как локально.
- **Данные** — только демо. В Neon нет суперпользователя, а сид сдвигает время через
  `session_replication_role`, поэтому база засевается локально (`demo-local.sh --fresh --dataset`) и
  переносится дампом (`pg_dump --no-owner`, триггеры создаются после данных); новые миграции — `platform:migrate`.
  Персоны демо-входа вшиваются в бандл и должны принадлежать именно этой базе.
- **Защита ADR-0009 не ослаблена в коде.** Vercel запускает функции с `NODE_ENV=production`, при котором
  демо-вход запрещён. Функция стартует только с явным `MODUS_HOSTED_DEMO=true` и лишь тогда передаёт тем же
  проверкам окружение демо. Без флага — отказ при старте.

## Последствия

- Любой, у кого есть ссылка, входит под любой демо-персоной и может менять демо-данные. Реальные данные
  сюда не загружаются. Восстановление — повторный перенос дампа.
- `MODUS_AUTH_SECRET` фиксирован в настройках проекта: несколько экземпляров функции принимают один токен.
- Ограничения Vercel: тело запроса ≤ 4,5 МБ (вложения до 5 МБ из ADR больше не пройдут целиком),
  холодный старт функции, время запроса ≤ 30 с.
- ИИ-помощник и расшифровка не подключены (`advisorModel: null`), интерфейс честно пишет «не подключён».

## Ограничения (не скрываются)

- Проверено 2026-11-13: `demo:world3d` против `https://modus-flow-demo.vercel.app` (сборка из `5df83a9`)
  прошёл 23 шага за 137 с; браузер — на ноутбуке, отрисовка программная (SwiftShader), не устройство показа.
  Холодный старт и нагрузка от нескольких зрителей не измерены.
- Собирать только из чистого коммита (отдельный `git worktree`): первая сборка взяла незакоммиченный код
  из рабочего дерева и упала на `/kingdom` — колонки его миграции в демо-базе нет.
- Остальные e2e-сценарии (`demo:<flow>`) против Neon не прогонялись.
- Дамп снят до миграции `0019` и догнан ею отдельно; данные `0019` (контекст проекта, эффект) в демо пусты,
  как и в локальном сиде.
- GitHub CI эти файлы не проверял.

## Открытые вопросы

- Перенос дампа вручную; автоматизировать, если демо по ссылке останется.
