# ADR-0040 · «Путь решения» и «Применить этот метод»

Status: accepted (задание владельца, 2026-11-13). Бизнес-права, атрибуция и правила XP не менялись.

## «Путь решения»

Знание уже хранило источники и хронологию. Новой истории не заведено: `platform/domain/knowledge-path.ts`
(чистый модуль) раскладывает уже записанные факты в путь с ветвями, `platform/modules/knowledge-path.ts` читает
их от имени читателя, под RLS.

- Ветвь — источник знания. Несколько источников — несколько ветвей; отклонённое предложение стоит рядом с
  внедрённым, отрицательный опыт не убирается.
- Узлы обращения: обращение → обсуждение в Совете (число записей и последняя рекомендация из закрытого списка) →
  решения → проверки (исход и число доказательств) → внедрение → подтверждённый результат. Шага, которого не
  было, нет. Итог ветви читается из фактов.
- Ствол — переходы самого знания: Летопись, Библиотека, Высший Архив, повторная проверка, «устарело».
- Источник, закрытый для читателя, — закрытая ветвь без названия, ссылки и событий. Текст людей (обоснования,
  карточки, реплики) в путь не копируется: узел ведёт на запись, где действует её собственный доступ.
- Глубина ограничена (6 ветвей, 9 узлов, 6 переходов, 8 применений); свёрнутое считается и показывается числом.
- Вид: колонки ветвей на широком экране, последовательность карточек на телефоне; тон статуса всегда словами.

## «Применить этот метод»

Существующий механизм `knowledge_applications` (повторное применение записывает куратор; подтверждено — когда
обращение внедрено) **не заменён и не изменён**. Добавлен один факт — миграция `0022_method_reuse.sql`,
таблица `idea_method_links`: «это обращение начато на основе этого знания».

- Кнопка открывает обычную подачу обращения (`#/new?method=<id>`); создаётся обычное обращение через тот же
  intake, маршрутизацию и правила решения. Автор — тот, кто применяет.
- Ссылку ставит только автор, только на знание, которое он может открыть, только на проверенное (Библиотека или
  Высший Архив) и не устаревшее; один раз; запись неизменяема. Единственный путь записи — функция базы
  `app_idea_link_method`; отказ отменяет и создание обращения (одна транзакция).
- Нажатие — не применение: уровень знания не меняется, условие Архива «нужно подтверждённое повторное применение»
  не выполняется, **XP не начисляется** ни замку, ни послу.
- Что показывается: «Применение ещё не подтверждено» — пока куратор не записал применение и обращение не
  внедрено; «Не применено: решено не внедрять» — отрицательный результат виден; «Применение подтверждено» —
  только из фактов.

## Проверка

`test/platform/method-reuse.test.ts` (12 тестов: права, приватность, одна транзакция, отсутствие XP, чужая
организация, неизменяемость), `npm run demo:living` — 15 шагов через реальные API, данные синтетические и
помечены. Снимки — `docs/demo/living-knowledge/`.

## Открытые вопросы владельцу

1. Должен ли автор обращения-применения сам отмечать «получилось / не получилось» отдельным действием? Сейчас
   итог читается из существующих фактов (решение, внедрение, подтверждённый эффект), новых прав нет.
2. Давать ли опыт автору исходного метода, когда его применение подтверждено у других? Сейчас — нет: это
   изменение правил XP и решается владельцем.
