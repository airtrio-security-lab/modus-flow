# «Живое Королевство» — демонстрация города и района подразделения

Люди и данные вымышлены, вход — имитация SSO. Всё, что показано, работает на реальных данных демо-базы;
ниже отдельно отмечено то, чего в системе нет.

## Подготовка

1. `./scripts/demo-local.sh --fresh` — чистые демо-данные (ИТ и закупки — «Японское княжество», склад —
   «Казахское ханство», продажи, пусконаладка и руководство — «Камелот», сервис и проектирование — «Монгольская держава»).
   Советы и чины цивилизаций — в [`councils-demo.md`](councils-demo.md).
2. Репетиция с проверками: `npm run demo:city` → «Сценарий «Живое Королевство» пройден» (≈ 13 с), затем снова
   `--fresh`.
3. Облегчённую графику выключить (Королевство → «Облегчённая графика: выкл») — иначе камера переключается
   мгновенно, без полёта.

## Расширенная версия (по пунктам мастер-промпта)

1. **Город.** Асель Темирова → Королевство. Кнопки камеры: «+», «−», «Весь город», «К Совету», «К Библиотеке»;
   перетаскивание мышью, клавиши (стрелки, + / −, 0). Камера не выходит за границы города.
2. **Районы разных цивилизаций.** Японское княжество (ИТ, закупки), Казахское ханство (склад), Камелот (продажи,
   пусконаладка, руководство), Монгольская держава (сервис, проектирование). Жители — по одному на пять человек отдела.
3. **Ханская ставка склада** — уровень 2 «Крепость», рядом посол обращения №2.
4. **Приближение** — колесо мыши или клик по замку (камера подлетает).
5. **Панель отдела** — шапка с главой, уровнем, XP, рейтингом и счётчиками.
6. **Карточки сотрудников** — группы «Состав», поиск по имени, должности или навыку.
7. **Руководитель выбирает специалиста.** Нужна задача, по которой Олег — ведущий или ответственный за
   решение после решения «внедрять». В демо-данных её нет (обращение №2 ведёт ИТ), поэтому сначала:
   Асель подаёт обращение в категории «Склад и логистика» → Олег на странице обращения «Принять решение» →
   «Внедрять». Затем район → «Состав» → карточка Ержана → «Назначить задачу» → «Назначить исполнителем».
   Это то же правило и тот же запрос, что на странице обращения.
8. **Профиль специалиста** — кнопка «Профиль»: должность, отдел, звание, компетенции, задачи (новая задача
   уже там), инициативы, результаты. Пожелания видит только сам сотрудник.
9. **Инициатива** — вкладка «Инициативы» или «Подать обращение».
10. **Посол** — обращение появляется на дороге от замка к Совету (Королевство).
11. **Королевское послание** — Асель → Уведомления → «Планёрка склада» → «Войти в Совет».
12. **Совет** — камера летит к дворцу («Пропустить» — сразу), открывается заседание или Круглый стол.
13. **Решение** — принимает ответственный за решение (Айгерим или глава отдела), не голосование.
14. **Внедрение** — исполнитель отмечает «Реализовано»; задача пропадает из колонки «Внедряется».
15. **XP** — +100 за подтверждённое внедрение, до +50 за подтверждённый эффект; один раз за событие.
16. **Район растёт** — при переходе порога уровень меняется, замок перестраивается, на площади появляется
    пьедестал достижения; «Развитие» показывает, какое обращение принесло опыт.
17. **Рейтинг** — «Площадь достижений» ведёт в рейтинг подразделений.
18. **Летопись** — «Внести в Летопись» на странице обращения; запись появится во вкладке «Наследие».
19. **Библиотека** — «Великая библиотека» в центре города; Высший Архив — соседнее здание.

Этот полный путь (шаги 9–19) уже автоматизирован в `npm run demo:final`; город и район — в `npm run demo:city`.

## Чего нет (говорить прямо, если спросят)

* Загрузка в часах, вакансии, требуемые компетенции — в системе не ведутся, поэтому «Нет данных».
* Специализация — из анкеты, которую заполняет сам сотрудник; это не подтверждённая квалификация.
* Отдельного зала Круглого стола с анимацией нет: после полёта камеры открывается обычный экран заседания.
* ИИ-советник без подключённой модели не работает как ИИ — это правила, и интерфейс так и пишет.
