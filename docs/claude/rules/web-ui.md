# Веб-интерфейс: правила (Phase 3)

- Интерфейс не владеет правилами. Что человеку можно — решает сервер; `lib/can.ts` только скрывает недоступное.
- Реальное имя компании — только в админке и документах. На игровых экранах — «Великое Содружество» и цивилизации отделов.
- Игровые титулы (Король, Регент) прав не дают и не выглядят как права. Личных рейтингов нет: замки — у отделов.
- «Нет данных» вместо нуля, когда данных нет. Ничего выдуманного: ни оценки ИИ, ни счётчиков.
- ИИ-помощник: демо-данные с видимой меткой; реальные данные — отдельный явный переключатель (ADR-0028).
- У каждого экрана есть состояния: загрузка, пусто, ошибка с повтором, нет доступа.
- Анимации уважают `prefers-reduced-motion` и «облегчённую графику» (`:root[data-lite='on']`); анимация из кода (WAAPI) проверяет это сама.
- Цвета берутся из токенов `styles.css`; сборка падает, если контраст ниже порога (`web/scripts/contrast.mjs`).
- Цель касания — не меньше 44 px; отступы учитывают `env(safe-area-inset-*)`.
- Меняющиеся числа — `font-variant-numeric: tabular-nums`: значение не сдвигает вёрстку.
- Запомненное на устройстве хранится под ключами `modus.*`, чтение и запись — в `try/catch`; экран работает и без хранилища.
- three.js загружается лениво, только при открытии 3D.
- Кинематографические уведомления — только через реестр `lib/cinematics.ts` (ADR-0031): сцена следует за фактом, который сервер уже записал этому читателю; ролик без проверенной озвучки и без реального события не подключается; просмотр ничего не меняет на сервере.
- Изменение, которое видит человек, закрыто после запуска сценария и сохранённого снимка в `docs/demo/<сценарий>/` — не по одному проходу типов.
