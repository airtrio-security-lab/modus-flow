# UI/UX pass against «UI UX Pro Max» rules

Date: 2026-11-10. Source of rules: the public skill `nextlevelbuilder/ui-ux-pro-max-skill`
(`references/quick-reference.md`, `references/pro-rules.md`, `data/products.csv`, `data/ui-reasoning.csv`).
Its search script was **not executed** (downloaded code is blocked in this environment); the rule files
and data were read directly.

**Product match** (data): «Productivity Tool» → flat design + micro-interactions, clear hierarchy +
functional colours, quick actions (~150 ms). The existing «Quiet Intelligence» direction already fits,
so the style was kept; the pass fixed rule violations.

## Fixed

| Priority / rule | Was | Now |
|---|---|---|
| 1 `color-contrast` | Secondary text `#848c90` 3.2:1; amber on tint 4.3:1; field borders 1.65:1 | `--ink-3 #60686c` (≥ 4.97:1), `--amber #97540a` (5.2:1), `--field-border` 3.1:1. `npm --prefix web run contrast` checks 19 token pairs × 2 themes and runs before every build |
| 1 `skip-links`, `focus-on-route-change` | None | «Перейти к содержимому»; focus moves to the main region on every route change |
| 1 `contextual-live-badge-updates` | Bare number in nav | «Уведомления: N непрочитанных» as the accessible name |
| 1 `focus-not-obscured` | Sticky submit bar covered the field with an error on phones | Bar is static on phones; `scroll-padding` keeps focused fields clear of sticky bars |
| 1 `dragging-alternative` | (already) «Перевести» on every card | kept |
| 2 `touch-target-size`, `tap-delay`, `press-feedback` | 32–40 px controls, no pressed state | ≥ 44 px on touch screens, `touch-action: manipulation`, pressed states, 120 ms colour transitions |
| 3 `progressive-loading`, `offline-support` | «Загружаем…» text; silent failures offline | Skeleton rows; offline banner explaining that the draft is kept |
| 4 `dark-mode-pairing`, `color-semantic` | Light only; hard-coded colours | All colours are semantic tokens; tonal dark theme (system, or «Тема» switch remembered on the device) |
| 5 `viewport-units`, `heading-line-balance`, `long-token-wrapping` | `100vh`, unbalanced headings | `100dvh`, `text-wrap: balance`, `overflow-wrap: anywhere` for user text |
| 2 `gesture-conflicts` / 5 `horizontal-scroll` | Board scrolled sideways on phones | One column at a time with a five-tab switcher |
| 8 `form-autosave` | Typed text lost on reload | Draft kept on the device, «Начать заново» to discard |
| 8 `input-labels`, `required-indicators`, `error-placement`, `focus-management` | Disabled button with a summary line | Required marks; errors under the field after blur (`aria-invalid`, `aria-describedby`); submitting with gaps focuses the first invalid field |
| 8 `sheet-dismiss-confirm` | Board dialog dropped typed reasons | Asks before discarding typed text |
| 9 `nav-label-icon`, `bottom-nav-limit` | Text-only tab bar | One SVG icon family (24 px grid, 1.75 stroke) + labels, ≤ 5 items |
| 9 `state-preservation` | Filters reset after opening an item | Search, filters, board scope and column kept for the tab session |
| 9 `empty-nav-state` | «Такой страницы нет» for pages the role cannot open | Explains who the page is for |

## Verified

* `npm run demo:e2e` (Playwright, real UI, fresh demo data): 11 steps pass, including draft restore and
  focus on the first invalid field.
* Screens at 390 px and 1280–1440 px, light and dark.

## Not done (honest list)

* No screen-reader session (VoiceOver/TalkBack); only semantics and focus order were checked.
* Largest system text size and landscape orientation were not tested.
* No route-level code splitting (bundle ≈ 250 kB, 76 kB gzip).
* Dark theme checked on the item page, board and lists; not every dialog state was captured.
