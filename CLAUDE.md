# MODUS FLOW — контекст для Claude

Перед началом каждой сессии и каждой задачи — «БисмиЛлях».

## Что это
Мультитенантная корпоративная платформа идей и подтверждённого вклада сотрудников.
Трек хакатона ГК «Модус Трейд» (система обратной связи и предложений). **Демо-день — 16 ноября 2026.**
Репозиторий: github.com/airtrio-security-lab/modus-flow. Демо запускается локально (docker compose).

## Структура
- `src/`, `public/`, `test/*.test.js` — старый прототип (не трогать без нужды)
- `platform/` — платформа v1: PostgreSQL + RLS, TypeScript без сборки (ADR-0005)
- `web/` — UI (Phase 3), e2e-сценарии в `web/e2e/`
- `docs/adr/` — все решения (0001–0042), `docs/architecture/`, `docs/audit/`
- `scripts/demo-local.sh` — локальное демо (`--ai`, `--dataset`)

## Команды
- `npm test` · `npm run typecheck` · `npm run verify` (полная проверка) · `npm run verify:quick`
- `npm run demo:start` / `npm run demo:seed` · e2e: `npm run demo:<flow>`
- Git-хуки: `npm run hooks:install`

## Решения владельца (не нарушать)
- Никто не принимает финальное решение по своей идее (независимый Decision Owner, в т.ч. гостевой ревьюер).
- Гибридные полномочия: руководитель отдела может сам решить простой запрос (не свой); с началом полевой проверки — двое разных людей.
- Отложить решение может только decision owner элемента; игровые титулы (Король, Регент) прав не дают; срок на паузе, пока отложено.
- «Королевство»: отдельный экран над теми же данными; замки — у отделов (без личных рейтингов), растут только от внедрённых идей; открытые элементы — послы, едущие на совет.
- Организация = одно Содружество («Великое Содружество»); отделы выбирают цивилизацию (Камелот, Японский сёгунат, Казахское ханство, Монгольская держава) — это стили, не отдельные тенанты. Реальное имя компании — только в админке/документах.
- ИИ-помощники (AI-Архивариус первым): облачная модель, Claude Haiku через Anthropic API; по умолчанию только демо-данные с видимой меткой, реальные данные — отдельный явный переключатель (ADR-0028).
- SSO через абстракцию OIDC; провайдер — после изучения инфраструктуры Модус Трейд.
- Старые PR #3–#7 — история/референс UX, не мержить.
- PR не объявлять готовым к мержу, пока реально не прошёл GitHub CI.

## Как работать
- Изменения аддитивные: новые классы/функции/блоки, без полных переписываний.
- Коротко и по делу.
- Новое архитектурное решение → новый ADR в `docs/adr/`.
