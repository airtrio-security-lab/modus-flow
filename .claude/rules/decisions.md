# Решения и отчёты: правила

- Новое архитектурное решение — новый ADR в `docs/adr/` с очередным номером и строка в `docs/adr/README.md`. Принятые ADR не переписываются: уточнение — новым ADR.
- В ADR есть раздел «Ограничения (не скрываются)»: что не сделано, не измерено, проверено только в эмуляции.
- Локальная проверка — не GitHub CI. Отчёт говорит, что именно запускалось и где. PR не объявляется готовым к слиянию, пока CI реально не прошёл.
- Старые PR #3–#7 — история и референс UX, их не сливают.
- Числа в документах — с датой и условиями замера. Программная отрисовка называется программной.
- `scripts/verify.sh` останавливается на первом упавшем шаге; шаги из него не убираются и не превращаются в предупреждения.
- Демо-данные вымышлены и так подписаны. Скрипты показа не используются с реальными данными сотрудников.
